# 0008. 回收语义与「机制完整性」：把假装是机制的三条规则真的收进服务端

- **状态**：已接受
- **日期**：2026-10-28
- **影响面**：协议 §2.2 / §2.3 / §4.2 / §5 / §7 / §11 / §12，实现 `src/space/*`
- **来源**：4 个独立 subagent 的对抗性 review（见 [ADR 0009](0009-verification-must-be-mutation-tested.md)）

## 背景

阶段 2 原型第一次验收拿到 25/25 全绿，于是标了「已完成」。随后 4 个独立 reviewer（不变式、协议一致性、安全并发、测试有效性）在**不共享上下文**的情况下各自审计，结论高度一致：

> **机制的外壳是真的，不变式的内部是空的。**

两个独立 reviewer 复现了同一个 P0：

| 缺陷 | 现象 | 命中率 |
|---|---|---|
| `claims_count` 终身不回退 | 一次租约过期 / 一次吊销后，任务停在 `PENDING` 但谁都认领不了；`attempts` 不再增长，`FAILED` 升级永不到达 | **100%**（任何 agent 崩溃/断线都是常态） |
| `sweepExpired` 读-判断-写跨事务边界 | 事务外的陈旧快照 + 无守卫的 `UPDATE`，能把**刚提交 DONE 的任务复活成 PENDING**（打破 R1），或把别人刚认领的租约覆盖掉 | 常态并发 |

更讽刺的是 R2/R3：

- **R2（回退不清零轮次）**：`slot`、`op`、`type` 全是客户端入参 —— 项目把它写在 AGENTS.md 里当作「机制优于自然语言」的正例，实际只是把自然语言挪进了三个字符串参数里。改个 `op` 尾随空格就重置轮次。
- **R3（硬门槛不得自行放宽）**：触发条件是 `payload.relax_hard_gate === true` —— **约束条件由被约束方自己填**，等于不存在。

## 决策

**把六处「看起来是机制」的东西真的收进服务端：**

1. **认领计数与重试预算分离**
   - `claims_count` 语义改为「**当前活跃认领数**」：`→PENDING`（回收/吊销/释放）时必须归零。
   - 重试预算只由 `attempts` 承担（sweep 时 SQL 自增，`≥3` 转 `FAILED`）。
   - `claims_max > 1` 在 v0.2 **显式拒绝**而不是假装支持——多成员竞争消费需要 `task_claims` 表（阶段 4）。

2. **回收必须是事务内的一次原子判决**
   - `select` 挪进 `BEGIN IMMEDIATE`；
   - `UPDATE` 带 `state + lease_until` 守卫并校验 `changes`；
   - `attempts` 用 SQL 自增，不用 JS 快照值；
   - 覆盖范围从 `CLAIMED/WORKING` 扩到**全部非终态**（`WAITING_INPUT/WAITING_AUTH/BLOCKED`），因为 agent 最可能崩在「挂着等人回答」的时刻。

3. **R2 的归属由服务端决定**
   - 客户端只报 `cp`（`CP1`/`CP2.1`/`CP2.2`/`CP3`/`CP4`/`CP5`/`3.4`），`slot` 由服务端查 §5.2 映射表得出；
   - `op` 从 `refs[0]` 指向的原任务取，忽略入参；
   - revision 只能对**自己可见**的任务开（否则别人 3 次调用就封死你的轮次预算）。

4. **R3 变成独立动作**
   - 删除 `payload.relax_hard_gate` 这条自报通道；
   - 新增 `space_task_accept({verdict, cp, gaps[], evidence{quantified_gap, exhausted_optimizations, design_contradiction}})`；
   - `verdict=relax` 只有 `human` 能签，三类证据缺一即拒；
   - **agent 侧没有任何放宽入口**。第 4 条按 §5.3 的意图实现，代价是 agent 遇到硬门槛只能 `FAILED` 或 `hold` 上报——这是刻意的。

5. **吊销 = 回收 + 改派 + 可解封**
   - 回 `PENDING` 时**同时**释放租约、清空认领计数、并把 `to_member` 改派为该成员的角色（否则回收后仍写着已吊销成员，别人照样接不了——换了个形态的卡死）；
   - token 过期走**同一条**回收路径；
   - 新增 `space token unrevoke`：吊销是运维动作，不该是死刑。

6. **一切客户端自报的量都要收口**
   - `lease_sec ≤ 3600`（否则 `1e9` 让任务 31 年不可回收）；
   - `max_block_sec ≤ 300` 且必须是有限数（`NaN` 会让 `wait` 永不返回）；
   - 消息 `text ≤ 1000` 字符、`to` 与 `topic` **二选一**（同时给会让「私聊」变成全员可见）；
   - 非有限数入参一律回退到默认值，不允许 NaN 流进 deadline。

7. **attach 成为硬前置**
   - 未 `attach` 时除 `space_attach` 外的工具一律 `NOT_ATTACHED`。否则跳过 attach 就等于绕过宪法版本闸门——那又只是提示词。

8. **读侧可见性 + scope 表化 + 心跳事务化**
   - `task_list` / `state_get` / `artifact_resolve` 按成员相关性过滤；
   - scope 声明下沉到 `mcp.mjs` 的 `TOOL_SCOPES` 表（新工具不声明就等于无保护，会立刻被 review 抓到）；
   - `task_heartbeat` 进事务并带 `owner/lease_id` 谓词（原实现能把别人刚拿到的 300s 租约砍成 2s）。

## 后果

**正面**

- 两个 100% 命中的 P0 消失：崩溃/断线后任务真的能回队并被别人接走，`attempts→FAILED` 真的会到达；
- R1 的破口（服务器自己复活终态）被关掉，`verify` 现在也会对账 handoff 交链与「终态之后仍有事件」；
- R2/R3 从「参数里的自然语言」变成「服务端查表 + 只有 human 能签」；
- 越权面收窄：跨成员认领、跨 op 轮次投毒、拿别人产物当 handoff、私聊泄漏、未 attach 使用工具，全部有回归断言。

**负面 / 代价**

- **R3 的代价是 agent 变笨**：遇到硬门槛只能上报等 human，不能自行「按已知限制收口」。这是有意的，但会让无人值守流程更容易卡住；
- `claims_max > 1` 显式拒绝意味着**广播竞争消费在 v0.2 不可用**，多成员抢同一广播任务会退化为先到先得；
- 每个写路径多了守卫与 `changes` 校验，代码变长；
- `unrevoke` 会复活该成员**所有**旧 token，粒度太粗（应改为按 prefix 选择）；
- 中断态进入回收范围后，**等人回答的任务会被租约踢回队列**——如果一个人工确认点要等两小时，需要把该状态的 `lease_sec` 调大（目前没有按状态区分租约预算，留到阶段 4）。

## 备选方案

| 方案 | 放弃理由 |
|---|---|
| 保留 `claims_count` 为终身计数，只在过期时专门重置 | 两个语义挤在一列里，正是这个 bug 的根源；不如拆开 |
| `sweepExpired` 改成后台定时任务，从读路径拿掉 | 原型没有调度器；而且「一次读写顺带回收」在单机规模下够用。**阶段 3 上 HTTP 后应改成后台 sweep** |
| revision 的 slot 继续由客户端报，但加签名 | 签名密钥还是服务端发，等于没解决「被约束方选边界」的问题 |
| R3 继续用 `payload.relax_hard_gate`，但要求 human 的 token | 仍然是「agent 不该填的字段 agent 能填」，删掉通道比校验通道更可靠 |
| 现在就实现 `task_claims` 表支持多成员认领 | 阶段 2 的验收标准不需要它；显式拒绝比假装支持诚实，也避免在没想清楚「重复劳动怎么合并」之前先做机制 |
