# 0003. 借用 A2A 的词汇与数据模型，不实现其协议

- **状态**：已接受
- **日期**：2026-10-28
- **影响面**：协议 / 接入层 / 未来互通路径

## 背景

A2A（Agent2Agent）是当前最主流的 agent 间通信标准，2025-04 由 Google 发起，2025-06 捐赠 Linux Foundation，**2026-03-12 发布 v1.0 稳定版**，2026-08 迁入 Agentic AI Foundation。

选型时逐项核对规范（以 v1.0 为准）：

| 我们需要的能力 | A2A 的状态 |
|---|---|
| 点对点任务委托 | ✅ 提供了 |
| 长任务 / 中断 / 恢复 | ✅ 提供了（`INPUT_REQUIRED`、`AUTH_REQUIRED` 为可恢复中断态） |
| 离线推送（webhook） | ✅ 提供了（但**要求对端有可达 URL**） |
| 任务不可变（终态不可重开） | ✅ 提供了（Task Immutability） |
| **房间 / 群组实体** | ❌ **协议未定义** |
| **成员资格 / ACL / 角色** | ❌ **协议未定义**（只有 per-skill OAuth scope 与无语义的 `tenant`） |
| **广播 / 多播** | ❌ **协议未定义**（只能对 N 个 endpoint 循环调用） |
| **共享黑板 / 共享状态** | ❌ **协议未定义**，且与"agent 是 opaque"原则**直接冲突** |
| **成员 presence 与目录** | ❌ **协议未定义**（registry API 规范不规定） |

即：**A2A 明确缺的，正好是本项目的核心。**

另外两个现实因素：

- **版本仍在结构级变动**：v0.3 → v1.0 是不兼容大改（枚举命名、判别字段移除、AgentCard 重组），半年后又整体迁入新基金会。规范本身还有已知内部矛盾（流式在中断态是否关闭，两处文档说法不一致）。
- **v0 不需要互通**：所有成员 agent 都是自有实现。

## 决策

**借用 A2A 的数据模型与词汇，不实现它的传输协议。**

具体借走：

| 借走的内容 | 用途 |
|---|---|
| `TaskState` 的三分类（活跃 / **可恢复中断** / 终态）与枚举语义 | 我们的任务状态机直接对齐，尤其 `INPUT_REQUIRED` 就是"人介入"的原语 |
| **Task Immutability** | 终态不可重开，修改须新建 revision 任务并引用原 id |
| `contextId` 分组 | 同一算子的任务归组 |
| `tenant` 字段（协议不赋语义） | 现成的挂载点，将来可用来放空间/组织 ID |
| **Extension 机制** | 将来把 room/broadcast 形式化为 A2A Extension 的正规出口 |

**切换触发条件**：出现第一个**非自有** agent 需要接入时。届时在空间服务外包一层 A2A Server 门面，**内部核心不动**（因为词汇已对齐）。

## 后果

**正面**

- 避免了「用它的传输层 + 自己写它缺的全部」的尴尬组合
- 不被一个仍在结构级变动的标准锁死
- 词汇对齐带来低成本的未来迁移路径：门面层可以把我们的状态映射到 A2A 的 `TaskState`，不需要改内部模型
- 中断态语义、任务不可变这些**设计经验免费获得**，比自己拍脑袋可靠

**负面 / 代价**

- 短期不与任何标准互通，一旦真需要，要写门面层（成本可控但非零）
- 自行设计的状态机与标准有差异（多了 `EXPIRED`、`REVISION_REQUESTED`、`CLAIMED`），映射时需处理
- 有"重新发明轮子"之嫌，需要持续关注 A2A 路线图是否补上群组能力

## 备选方案

| 方案 | 放弃理由 |
|---|---|
| 直接实现 A2A Server 当空间 | 它缺房间/成员/广播/黑板，等于用它传输层 + 自己补全部空间语义，还被迫接受其版本变动 |
| 直接采用 ACP（IBM/BeeAI） | **已被 A2A 吸收合并**，官方文档首屏即迁移提示，属历史选项 |
| 采用 AGNTCY | 它的发现 / 身份（可验证凭证 + 访问控制）/ 消息 / 可观测**最接近本项目需求**，但主要面向跨组织互联网规模，v0 用它过重。**留作跨组织需求出现时的首选评估对象** |
| 完全自创、不看标准 | 失去免费的设计经验（中断态、任务不可变），且未来互通成本更高 |

## 备注

一个重要反向发现：**A2A 没有租约概念**，因为它同步请求-响应，连接在即人活着。而我们的成员是"会崩、会被人关掉的 session"，**必须靠租约回收**。这提示：对齐标准时不要为了"一致"而删掉 `EXPIRED` 与租约机制——我们面对的是不同问题。
