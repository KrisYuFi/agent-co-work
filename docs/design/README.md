## 阅读提示

`protocol-v0.1.md` 是**语义定义**，不是实现方案。它回答"系统必须满足什么"，不回答"用哪个框架写"。

其中几节是理解成本最高、也最关键的：

| 节 | 为什么重要 |
|---|---|
| §1.1 三个平面 | 决定了整个系统的形状；「消息只传引用」是后面所有设计的支点 |
| §3 事件流与状态归约 | 回答了最难的问题：**谁写状态**。答案是「只有 server」 |
| §4 任务状态机 | 借用了 A2A 的词汇，额外补了 `EXPIRED` 与 `REVISION_REQUESTED` |
| §5 服务端不变式 | 把原来靠提示词记着的规则变成**拒绝写入**。这是本项目"机制优于自然语言"的落地点 |
| §6 唤醒模型 | 全套方案压在它上面，**阶段 1 已实测验证成立**（[`probe/RESULTS.md`](../../probe/RESULTS.md)）；残留约束见 ADR 0005 |

## 变更约定

- 协议语义变更 → 升版本号（`protocol-v0.2.md`），**不覆盖旧版本**
- 旧版本标为「已被 vX 取代」并保留，便于回溯设计演进
- **例外：草案（未实现）阶段且无外部消费者时**，修订合并进当前版本并记入文首「变更记录」表。一旦有实现或外部接入方，回到上面的分文件规则
